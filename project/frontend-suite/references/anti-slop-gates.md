# 去 AI 味品質閘門與操作模式（Anti-AI-Slop Gates & Modes）

> 吸收自 `Nutlope/hallmark` v2 核心設計方法論，並結合本倉庫預設美學原則，提供**新建設計流程（Build）**、**三級品質閘門（Floor / Reflex / Finish）**，以及針對既有網頁的 **Audit / Redesign / Study** 三大安全操作模式。

---

## 一、四步防失控建置流（Build Runbook）

在撰寫任何頁面程式碼前，依序完成以下四步，避免 AI 直接套用「置中大字 + 三欄特色卡 + 紫藍漸層」模板：

### Step 0：Pre-flight 盤點（先問先查，禁捏造）
1. **盤點既有資產**：先讀取目標專案現有的色票、字體設定、UI 框架與不可動搖的業務規格。
2. **確認真實素材**：若使用者尚未提供真實文案、數據、圖片或聯絡資訊，**先列出缺口並詢問**，嚴禁自行捏造「99.9% 滿意度」、「10,000+ 企業採用」或假見證人頭像／評語。

### Step 1：任務導向定調（Built from the Job）
- 依照使用者頁面的**實際工作任務**選擇資訊架構，而不是倒過來套用漂亮版面：
  - **工具／數據儀表板**：優先採用全域規則之暖米白底（`#FAF7F2` / `#F6F4EE`）、石墨深炭灰（`#1E2022`）、暖灰細線（`#E5E0D5`）、克制圓角（`rounded-md`）與高資訊密度狀態邊條。
  - **簡報／品牌／多風格網頁**：從 `themes/*.md` 挑選合適色票，或依 `references/theme-factory.md` 與專案調性從零建立自訂 `:root` token（Custom 模式）。

### Step 2：Hero 先行隔離審查（Hero-First Isolation）
- 先單獨實作**首屏主視覺（Hero）**，不急著一口氣生出整頁 6～8 個區塊。
- 寫完 Hero 後停下來冷靜檢查：
  - 視覺焦點是否集中（只在一處大膽，其餘克制）？
  - 標題與副標是否不依賴無意義的 ALL-CAPS 眉標（eyebrow）或單字變色來撐場面？
  - 確認 Hero 比例與氣質過關後，再往下實作其餘區塊。

### Step 3：自動化閘門 + 多寬度實測
1. **靜態掃描**：執行純 Python 檢查腳本，先清掉所有 `FLOOR` 違規與不必要的 `REFLEX` 警訊：
   ```bash
   python scripts/slop_lint.py <目標檔案或資料夾>
   ```
   （若要求零警訊可加上 `--strict-reflex`；需機器讀取可加 `--json`。）
2. **動態渲染與多寬度檢查**：搭配 `references/webapp-testing.md` 使用 Playwright 驗證桌機（`1440px`）、平板（`768px`）與手機（`375px`）三個寬度無橫向卷軸溢出。

## 二、三級品質閘門（Floor / Reflex / Finish）

| 等級 | 定位 | 核心檢查項目 | 處置原則 |
|---|---|---|---|
| **Floor（底線）** | **零容忍**，違反即判定不合格 | 1. 互動元件必須具備 `:focus-visible` 鍵盤焦點框<br>2. 含動態/轉場時必須提供 `@media (prefers-reduced-motion: reduce)` 或 `motion-reduce:`<br>3. HTML 完整頁面必須具備 `<meta name="viewport" ...>`<br>4. 嚴禁使用 `transition: all`，須明確指定動畫屬性<br>5. 色彩對比度達標、手機版無橫向破版<br>6. 嚴禁殘留 `Lorem ipsum`、假公司或捏造的統計指標 | **必須修到過**，不得略過或放寬 |
| **Reflex（警訊）** | **AI 常見套版習慣**，預設攔截 | 1. 紫藍漸層背景或按鈕（`from-indigo/purple` + `to-blue`）<br>2. 預設科技深藍（`#0F172A`）或全頁純白刺眼底（`#FFFFFF`）<br>3. 過度使用大圓角（`rounded-2xl` / `rounded-3xl` 泡泡感）<br>4. 在標題、按鈕、導覽內直接用 Emoji 當圖示<br>5. 標題上方硬加高字距全大寫眉標（ALL-CAPS eyebrow）<br>6. 用中點 `·` 串接多段標籤（如 `Fast · Simple · AI`）<br>7. 出現 `href="#"` 空連結或無作用的假表單<br>8. 同質化三欄等寬特色卡網格、卡片包卡片 | **預設應清除**；僅當使用者明確指定該視覺風格時，才可附註原因保留 |
| **Finish（工藝）** | **細節打磨**，不阻擋交付但顯質感 | 1. 行長控制（正文 `< 80` 字元）與版面垂直節奏<br>2. 數字欄位使用 `tabular-nums` 等寬對齊<br>3. 操作狀態回饋與錯誤提示一致（按鈕寫「儲存變更」，提示寫「已儲存」） | 於收尾階段順手精修 |

## 三、既有專案三大操作模式（Audit / Redesign / Study）

當任務不是「從零新建」，而是處理既有網頁或參考案例時，依需求切換以下模式：

### 1. Audit 模式（只健檢、不改檔）
- **適用時機**：使用者想先知道現有網頁哪裡有 AI 味、破版或無障礙缺口。
- **執行規則**：
  1. 先跑 `python scripts/slop_lint.py <target>` 取得靜態掃描結果。
  2. 對照上表「三級品質閘門」與 `references/design-principles.md` 進行版面與文案體檢。
  3. 產出分級修正清單（`FLOOR 必修` / `REFLEX 建議調整` / `FINISH 打磨`），**嚴禁改動目標程式碼**。

### 2. Redesign 模式（安全翻新、功能不變條約）
- **適用時機**：將既有「AI 味很重」或簡陋的網頁重新排版與美化。
- **核心不變條約（Invariants）**：美化過程中，**嚴禁遺失或破壞原有功能與資訊**。改版前後必須核對：
  - 所有 `<a href="...">` 連結路徑與文字語意完整保留。
  - 所有 `<form>`、`action`、`input[name]`、`id` 與必填屬性完整保留。
  - 所有既有按鈕點擊事件、資料綁定、API 呼叫與 JS selector 仍能正常觸發。
  - 真實業務文字與數據完整保留，不得擅自改寫或刪減重要條目。
- 改完必須執行 `slop_lint.py` 並做前後功能與視窗寬度核對。

### 3. Study 模式（設計 DNA 萃取）
- **適用時機**：使用者提供參考網站或截圖，希望做出相近質感但不想抄襲套版。
- **萃取維度**：只分析並記錄以下 4 項設計 DNA，再套入目標業務內容：
  1. **色階比例**：背景／表面／文字／單一強調色的面積佔比。
  2. **字體階級**：主標題與正文的字級倍率、字重對比與行高。
  3. **版面節奏**：留白密度、欄位切割比例與區隔手法（留白 vs. 細線）。
  4. **克制原則**：全頁最吸睛的單一焦點是什麼，其餘元素如何退居背景。
