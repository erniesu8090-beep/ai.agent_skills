# Colab 筆記本排版與實作規範

## 1. 格子順序（固定）

| 順序 | 格子 | 內容 |
|---|---|---|
| 0 | 說明（Markdown） | 標題（一個 emoji ＋ 專案名稱：用途）、一句話說明、資訊表（執行階段：L4／A100／G4 GPU 建議、預估時間、要準備、會得到）、「🚀 使用方式」編號步驟、⚠️ 注意事項 |
| — | `## ⚙️ 設定` | 小標題（供左側目錄導覽） |
| 1 | ⚙️ 設定 | 所有可調整參數，只放 `# @param` |
| — | `## ▶️ 執行` | 小標題 |
| 2 | 🧰 準備：載入顯示工具 | 骨架內建，原樣保留 |
| 3 | 1️⃣ 確認有分到 GPU | 沒分到就顯示 ❌ 與切換步驟並停止 |
| 4 | 2️⃣ 建立環境並安裝套件 | 已安裝就略過；最後顯示套件版本表 |
| 5 | 3️⃣ 準備輸入 | 上傳檔案或掛載雲端硬碟 |
| 6+ | 4️⃣… 執行 | 一格只做一件事 |
| — | `## 📦 結果` | 小標題 |
| 最後 | N️⃣ 打包並下載結果 | 打包 zip、顯示大小、說明放回本機哪個資料夾、下載 |

## 2. 每一格的寫法

- 程式格第一行：`# @title N️⃣ 動詞開頭的步驟名稱 { display-mode: "form" }`，讓 Colab 預設顯示標題並摺疊程式碼。
- 第二行用 `# @markdown` 寫一句這格在做什麼、使用者要做什麼（例如「按下方選擇檔案」）。
- 一格只做一件事；需要使用者互動的步驟（上傳檔案、雲端硬碟授權）獨立成一格。
- 說明格與 `@title`、`@markdown` 使用繁體中文；Markdown 說明格只放一層 `#` 大標題，其餘階層用 `##`、`###`（搭配 `metadata.colab.toc_visible: true` 讓左側目錄自動展開）。
- 每格都要能安全重跑：偵測到已安裝或已完成步驟時，用 `info()` 提示並略過，不要重複執行或報錯。

## 3. 參數集中管理

- 所有可調整的值集中於「⚙️ 設定」格，使用 Colab 表單語法 `# @param`：
  - 勾選框：`OPTION_A = True  # @param {type:"boolean"}`
  - 下拉選單：`LEVEL = "200"  # @param ["150", "200", "300"]`
  - 數字：`BATCH_SIZE = 4  # @param {type:"integer"}`
- 後續格子只讀取這些變數，不再出現寫死的設定值。
- 參數旁可用 `# @markdown` 註明影響（例如「越高越清楚、越慢」）。

## 4. 輸出與進度呈現

- 只使用骨架「🧰 準備」格提供的函式：`ok()`、`warn()`、`fail()`、`info()` 卡片，`table_html()` 表格，`logbox()` 可展開長訊息。不要用 `print` 輸出大段文字。
- 執行系統指令一律用 `sh(指令, "中文標題")`，不用 `!指令`：成功只顯示 ✅＋秒數，失敗顯示 ❌＋最後 40 行訊息並停止「全部執行」。
- 需要中止後續執行時 `raise StopRun(...)`，隱藏整片 Python 錯誤追蹤。
- 長時間程式用 `subprocess.Popen` 逐行讀輸出：子程式印出 `@@` 開頭的進度標記（例如 `@@TOTAL 10`、`@@STEP 3`、`@@PAGE 名稱 3`），主格解析後用 `display(..., display_id=True)` ＋ `.update()` 原地更新進度表；其他雜訊不顯示於畫面，完整輸出寫進 `result/_run_log.txt` 一併打包。
- 跑完顯示彙總表（每項耗時、資源用量、✅／❌）；失敗項目另外用 `fail()` ＋ `logbox()` 顯示錯誤最後 15 行。
- 顏色只使用卡片內建的四種；表格邊框使用半透明灰（`#8884`／`#8883`），確保深色、淺色主題皆清晰可讀。

## 5. 硬體加速器（GPU）選擇指引

專案使用 GPU 雲端算力（影像／影片生成、大語言模型推論、版面分析等）時，說明格與第 1 格應標明建議 GPU。

> **核心原則**：各 GPU 型號影響的是**推論速度（耗時）**與**顯示記憶體上限（VRAM，可載入模型大小）**；在相同模型權重與參數下，**產出的畫面品質與物理效果完全相同**。

| 硬體選項 | 架構與顯存 (VRAM) | 特性與生成耗時 | 適用情境與建議 |
|---|---|---|---|
| **L4 GPU** | NVIDIA Ada Lovelace<br>**24GB VRAM** | **標準速度**<br>支援 BF16/FP8，顯存充裕，生成時間適中 | **預設首選（CP 值最高、最省點數）**。<br>Colab Pro 標配；畫質同旗艦卡，適合日常算力與完整流程驗證。 |
| **A100 GPU** | NVIDIA Ampere<br>**40GB / 80GB VRAM** | **極速**<br>大顯存與高頻寬，耗時明顯短於 L4 | **長篇大量運算首選**。<br>適合不想久候、處理超長影音或同時載入多大型模型時使用。 |
| **G4 GPU** | NVIDIA Blackwell<br>(RTX PRO 6000 Server 等級，**96GB VRAM**) | **最快旗艦**<br>最新架構與超大顯存，耗時最短 | **旗艦極速配置**（見於 Colab Pro+ 或特定選單）。<br>耗點較多，適合追求極限速度或超大顯存需求。 |
| **T4 GPU** | NVIDIA Turing<br>**16GB VRAM** | 較慢，不支援 BF16，大模型易記憶體不足 (OOM) | 僅適合輕量影像處理、文字分類或教學測試；**現代 DiT 影音生成不建議使用**。 |

- 開頭資訊表應註明「追求省點數選 L4，追求速度選 A100 或 G4；成片畫質皆相同」。
- 「1️⃣ 確認有分到 GPU」格應相容 L4、A100、G4、T4 等不同卡別，在卡片顯示實際分到的卡名、顯存大小與友善提示。

## 6. 獨立 Python 環境隔離

- Colab 內建套件與專案版本容易衝突，使用 `uv` 建立獨立環境 `/content/venv`（Python 版本與專案 `.venv` 相同），套件版本與專案 `requirements.txt` 一致並鎖定。
  - 已知衝突案例：Colab 內建 PyTorch 與 Paddle 存在 NCCL 符號衝突（`undefined symbol: ncclCommWindowDeregister`）；若直接卸載內建 PyTorch 會留下殘缺模組（`No module named 'torch.multiprocessing'`）。改用 `/content/venv` 獨立環境即可避開。
- 安裝完成後以 `/content/venv/bin/python` 執行一次環境檢查（匯入主要套件與確認 GPU 可用），透過 `@@VER` JSON 標記回傳並用 `table_html()` 顯示成版本表。

## 7. 輸入、輸出與程式碼來源

- **小檔案**：`files.upload()` 上傳，顯示檔名與大小；結果以 `shutil.make_archive` 打包後用 `files.download()` 下載。
- **大檔案或長時運算（防斷線）**：`drive.mount("/content/drive")` 掛載雲端硬碟，將中間結果邊跑邊存至雲端硬碟，斷線重連後可從中斷處接續。
- **專案程式碼來源**：
  - 少量腳本：直接內嵌在格子裡（`script = r"""..."""` 寫檔後用 `/content/venv/bin/python` 執行）。
  - 較多檔案：由使用者上傳專案 zip 或置於雲端硬碟。
  - 私人 GitHub 倉庫 Token 或 API Key：請使用者存放在 Colab 左側「🔑 密鑰」，程式碼透過 `google.colab.userdata.get()` 讀取，嚴禁寫進筆記本。
